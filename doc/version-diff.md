# 两版文本差异（SANA EDITION）

> 两版的逐脚本结构核对结果为零结构差异，判据：`script/align_check.py`。

## 1. 两版是什么

| | 民汉补丁（绿茶汉化组 SANA EDITION 汉化） | Steam 版 |
|---|---|---|
| 组成 | `mashiro_sana_chs.xp3`(264 MB, 115 脚本) + `mashiro_sana_cn2.xp3`(141 KB, 3 个 H 脚本) + `patch.xp3`(15 MB，与 FHD 补丁同名文件 **md5 相同**) | `data.xp3` + **`patch.xp3`**（1.10 GB，官方补丁，补齐内容用）+ `patch2.xp3`（2.09 GB，无剧本） |
| 母体 | 日文原版《純白交響曲 SANA EDITION》 | 同一部游戏的 Steam 版 |
| 文本载体 | 明文 xp3 里的 `*.scn`（`mdf\0` 外壳 + zlib + PSB） | Hxv4 加密 xp3 里的裸 PSB |
| 每个脚本的副本数 | 1 | **3**（`cn/scn/`、`tw/scn/`、`en/scn/` 三域各一份，结构完全相同） |
| 提取结果 | `resource/chs_text/`：**118 脚本 / 28,254 行 / 11 选项** | `resource/steam_text_zhcn/`：**102 脚本 / 23,245 行 / 11 选项** |

### 1.1 `patch.xp3` 是完整版的前提（关键）

Steam 版**只装 `data.xp3` 时内容是不完整的**：`cn/scn/` 只有 40 个脚本 / 10,496 行，而且是"路线限定"版本
（`scenario_01/02` 被裁、`scenario_sana_route01..04` 各少十几到上百行、`route05..08` 与 `seアフター_*` 整段缺失）。
官方 `patch.xp3`（1.10 GB）覆盖 40 条同名脚本并补上另外 62 条 ⇒ 102 脚本 / 23,245 行。

判据（可复跑）：分别只提 `data.xp3` 与 `data.xp3+patch.xp3`，行数 10,496 vs 23,245；
残缺版与民汉的差集 = 23 个脚本共 858 行"民汉有、Steam 无"，而完整版与民汉 **零差异**。

⇒ 本项目**要求游戏装有官方 `patch.xp3`**（Steam 正常安装即自带）。缺它时补丁仍不会崩，但会注入游戏并不会请求的脚本、且被覆盖的 40 个脚本会带上多出来的行。

## 2. Steam 侧怎么取到的（结论，可复跑）

Steam 版 xp3 全为 Hxv4 加密，参数 `resource/hxv4/profile_live.json` **与 FHD 项目通用**（实测映射表 tag 通过、
内容过滤器正确，`data.xp3`/`patch.xp3` 全量条目都能解）。整条链路离线：

```bash
mamba run -n GalRev python script/extract_text.py \
    "<游戏目录>/data.xp3" "<游戏目录>/patch.xp3" \
    --profile resource/hxv4/profile_live.json --domain 9D31BC7AA367A8F1 --out resource/steam_text_zhcn
```

- 两个归档的**顺序不能反**：`patch.xp3` 覆盖 `data.xp3`（工具按"后传入者胜"处理，`_index.json` 的 `overridden=40` 就是这 40 条覆盖）。
- `patch2.xp3` 与剧本无关：22,118 条目里 `cn/scn`/`tw/scn`/`en/scn` 三域**零条目**（域是高编号的图/音/语音目录）。
- 三域同构：`cn` / `tw` / `en` 各 102 脚本 / 23,245 行 / 11 选项，脚本集与行数逐脚本相同 ⇒ 匹配结论可跨域复用，回写要用目标域自己的 `text_idx`/`length`。
- `data_sana.xp3`（704 MB / 3,799 条目）**不含剧本**：全部落在根域，其中只有 9 个 PSB 且都不是 `scenes` 结构（UI/配置类）。

| 指标 | 结果 |
|---|---|
| 对白行 | 23,245 = 23,245，**逐脚本行数全等** |
| `(scene, row)` 键序列 | **102/102 全等**（无重排、无增删） |
| 每行页数 | 23,245 行全等 |
| 有语音的行（`pages[].voice`） | **10,964，voice id 100% 相同** |
| `char_id` | 23,245 页全等 |
| `speaker` 有无 | 23,245 行全等 |
| 选项 `index` | 11/11 全等（无双侧不一致） |
| 名字哈希覆盖 | 102/102 脚本的 `blake2s(<名字>.scn)` 在游戏 `cn/scn` 域存在 |

⇒ **位置映射成立**：`(script, scene, row, page)` 四元键一一对应，回写不需要重排或模糊对齐，与 FHD 本篇阶段的结论同类（`doc/text-model.md` §6.3）。

## 5. 文本层面的差异（影响回写）

1. **引号风格**：民汉 `「……」`，官方简中 `“……”`（繁中 `「」`）。回写采用民汉风格。
2. **分页元数**：民汉 28,254 页里有 **9,576 页是 5 元分页**（`text` + 去换行的 `text_plain`），Steam 23,245 页里只有 **51 页**带 `plain`。回写只写 `text` + `length`，**不要**生成 `plain`。
3. **`alt_speaker`（逐页说话人覆盖）**：Steam 有 15,064 处、民汉 0 处，方向是**单向**的（没有"民汉有、Steam 无"的情况）⇒ 回写时保留 Steam 自己的 `alt_speaker` 不动即可。
4. **`length` 口径不同**：民汉把 `%NNN;`、`#RRGGBBAA;` 等标记算进长度，官方不算（Steam 侧 24 个脚本共 51 页可证）。回写统一用 `tool/scn.py::page_length()` 按**目标版口径**重算。
5. **民汉自身残留**：28,254 行里有 10 行仍含假名（落在 102 个共有脚本内），属于人名/拟声或漏译，回写前需单独处理（`resource/match/_stats.json` 的 `source_untranslated=10`）。
6. **与 FHD 补丁的关系**：民汉 SANA 补丁的 118 个脚本 **FHD 补丁全都包含**（FHD 277 脚本是其超集），其中 100 个逐行完全相同，18 个是后续修订（`庆功会/庆功宴`、`呆在/待在`、`目光/眼光`、`２７号/27号`…）⇒ 以 **SANA 补丁为准**，FHD 那份不参与本仓库。

## 6. 匹配结论

对齐表：`resource/match/pairs/<script>.jsonl`（23,245 行），统计：`resource/match/_stats.json`。

| status | 行数 | 含义 |
|---|---|---|
| `aligned` | 10,955 | 两侧 voice id 相同（决定性锚点） |
| `needs_review` | 12,280 | 无语音的叙述行，结构与行号已对齐，需要语义抽查 |
| `source_untranslated` | 10 | 民汉仍是日文（见 §5.5） |

因为结构零差异，`needs_review` 不再是"要不要对齐"的问题，而是"抽查译文质量"的问题；
`_stats.json` 的 `suggested_batches` 给出 11 批约 10 脚本的切分，供人工/LLM 抽查使用。

## 8. 回写与出包结果

命令链（全部可复跑，`mamba run -n GalRev python …`）：

```bash
script/writeback.py fetch        # 102 脚本 -> tmp/zhcn_psb（data.xp3 40 + patch.xp3 102，后者胜）
script/writeback.py roundtrip    # 闸：102/102 零改动往返逐字节一致；民汉侧 118/118 ok
script/writeback.py apply        # -> tmp/out_zhcn + tmp/_report_apply.json
script/pack_patch.py             # -> releases/CN.xp3（Hxv4，3.1 MB，自校验）
script/verify_patch.py           # 独立闸：从 resource/ 重建期望，逐页比对产物
```

`apply` 统计（23,245 页）：

| 项 | 数值 | 说明 |
|---|---|---|
| `slot_rewritten` | 22,111 | 原位改写字符串槽 |
| `slot_appended` / `ref_repointed` | 147 / 292 | 官方去重导致一槽多页，追加新槽并原位改引用 |
| `len_patched` / `len_already_ok` | 19,004 / 4,220 | `length` 按目标版口径重算 |
| `select_written` | 9（+2 条两侧文本相同） | 11 个选项全覆盖 |
| `page_kept_official` | 10 | 民汉残留日文，保留官方译文 |

`verify_patch.py` 独立复核：**23,238 / 23,245 页**与期望完全一致，7 页属于已知原位限制：

| 类型 | 页数 | 后果 |
|---|---|---|
| `ref_width_too_small` | 4 | 字符串引用只有 1 字节，新槽号（306/307）放不下 ⇒ 保留官方译文（`“欸？”`×2、`“我也……不知道该怎么做才好了！”`×2） |
| `page_ref_shared` | 3 | 两行共用同一个页对象（官方把相同页去重），只能写多数票译文 ⇒ 该页显示相邻行的中文（`scenario_03` r299、`scenario_miu_psp_route01_2_07` r328、`１２月２４日（木）_02（Ｈ１）` r307） |

这两类限制与姊妹项目同类（那边 13 + 3 页），根因是"文本引用与页数组都是定宽内联字段"，要彻底解决必须写完整对象图序列化器，收益（7 页）与风险不成比例，故接受。

产物：`releases/CN.xp3` = 1 个警告占位 + 1 个钩子（根域 `default.tjs`，27,780 B = 本作原文 25,398 B + 钩子）+ 102 个脚本，共 3.1 MB。回读校验：条目名哈希 102/102、payload 逐字节一致、adler 全通过。
**实机**：简中下剧情为民汉译文；语音对应、存档读写、删包回退的判据见 `doc/acceptance-criteria.md` §4。

**可复跑性**：清空 `tmp/` 后重跑 `fetch → apply → pack_patch → verify_patch` 全程 **84 秒**，产物 md5 与首次完全一致（`4e792bd3034837b6ae8c6b676457e223`）。改文本只需改 `resource/chs_text/` 后重跑后两步。

## 9. 语义抽检的结论

结构闸（§4）证明"行数、页数、voice id、`char_id`、选项全等"，但证明不了"同一行号两侧是同一句原文"。
为此按"从脚本末尾往前抽样 + 二分定位"做了一轮人工/LLM 抽检（取样器是一次性脚本，未入库）：

| 项 | 结果 |
|---|---|
| 规模 | `needs_review` 最多的 5 个脚本 × 尾部 20 条 = **100 条**（占 12,280 条待检行的 0.8%） |
| 脚本 | `scenario_03`、`１２月２４日（木）_02（Ｈ１）`、`scenario_miu_psp_route01_03`、`seアフター_02（Ｈ３）`、`scenario_02` |
| 全 `ok` | 4 个脚本（尾部 20 条均判为"同一句的两个译本"） |
| 唯一发现 | `scenario_02` **pos=429 / row=407** 一处 `merge`（切句边界不同，`delta=0`） |
| **行位移** | **0 处** ⇒ 位置映射成立，`script/writeback.py` 无需偏移逻辑 |

`scenario_02` pos=429/430 的细节：

| 侧 | row 407 | row 408 |
|---|---|---|
| Steam | 完全是不欢迎我们的表情。**晨光透过她的长发，衬托出端正的五官。** | 这股压倒性的存在感让各务台的学生都安静了。 |
| 民汉 | 摆明了是那种完完全全不欢迎我们的表情。 | 她那背负晨光而显得晶莹透亮的长发与清秀的姿容，`\n`无一不散发出绝对的存在感，令各务台学院的全体学生陷入了沉默。 |

**处置 `no_action`**：位置写入后回读 `CN.xp3`，row 407 =「摆明了是那种完完全全不欢迎我们的表情。」、row 408 =「她那背负晨光而显得晶莹透亮的长发与清秀的姿容，`\n`无一不散发出绝对的存在感，令各务台学院的全体学生陷入了沉默。」—— 两句各自语义完整，无重复也无丢失（「晨光…五官」在民汉版本就是 row 408 长句的一部分），row 409 的 `mc013` 语音锚点亦正常 ⇒ 不修补文本、不引入偏移映射。

记录：`resource/match/offsets.jsonl`（当前 1 条，人工确认）。

**判读注意**：`pos` 是 pairs 文件的记录序号（全局唯一），`row` 是**场景内**行号——本作 9 个脚本有多个场景，第二段起 `pos != row`（`scenario_02` 就是 `*start` 456 条 + `*conf` 22 条）。引用位置时两者都要写清楚。

**剩余风险**：覆盖 0.8%，未抽到的脚本理论上仍可能有局部切句差异；但"行位移"这类会造成整段错位的错误，在"结构零差异 + 4/5 脚本尾部全 `ok` + 唯一发现是 0 位移的 `merge`"这一组证据下没有存在迹象。
要提置信度就按同样方式继续抽末段，结论更新本节即可。
